# Agent Note: 带存储背景图片的桌面 Nord 主题插件

Status: implemented

[English](2026-09-12-desktop-nord-theme-plugin.md) | 中文

## 问题

桌面应用只有一种固定外观：`ui-theme` 声明的内置亮/暗配色。想要别的颜色、或者想在界面后面放一张背景图片的用户，没有任何受支持的途径。Web 客户端已经暴露出此类插件需要的扩展点——`ctx.theme.overrideTokens` 按来源叠加别名 token——但桌面组合里没有任何东西使用它。

更难的是分发路径。桌面安装器只接受 `registry.npmjs.org` 上的包名，并固定了一份空的用户 npm 配置，因此第三方插件根本无法装进用户 profile；编译后的应用也无法接收用于挂载 `--patch` 覆盖文件的启动参数。能落地的东西必须位于应用自身的运行时闭包内。

## 决策

`@deepseek-ai/dsh-client-ui-theme-nord` 是 dsh 家族的发布成员，桌面组合以内置行方式挂载它（`apps/desktop-host/config/desktop.cordis.patch.yml`，由 `apps/desktop-host` 的依赖解析）。由于它不是 private 包，dsh 发布打包会像其他家族包一样把它带进运行时闭包，这正是两个半部都能出现在应用打开的 profile 上的原因。

配色是每个色彩方案十个色址——底色、三层表面、文字、两个品牌色，以及三个状态色。`buildTokens` 由这些色址派生出 ui-theme 样式表声明的每一个 `--dsw-alias-*` 与 `--dsw-specific-*` token；浏览器半部把结果作为单个覆盖层叠加到 `ctx.theme` 上，因此调整一个色址会移动所有读取它的表面，外观在亮/暗之间切换也照常工作。

调色面板是「插件」分节的标签页。修改是暂存的：每次修改都重建该层，窗口立即跟随取色器变化，而设置文档只在用户保存时写入。设置 scope 仍是权威——控制器从分节读回被接受的值，而不是自行预测，因此被拒绝的写入会作为未保存草稿保持可见。

背景图片存放在设置文档之外。Host 半部通过 Remote 命名空间（`themeWallpaper`）接收 base64 字节，校验媒体类型与 8 MiB 上限，并把它们写入 `$DSH_HOME/theme-wallpaper/{sha256}` 及一个 `.type` 兄弟文件；设置文档只携带哈希与媒体类型，因此设置链路与持久文档都不传输图片字节。图片引用与其他改动一起保存，而字节在用户选中时就写入，因为存储按内容哈希寻址：被放弃的选择只会留下无人引用的文件，而不是错误的背景。

图片以两层绘制在所有流内元素之后——持有配色底色的不透明底板，以及其上方按暂存不透明度绘制的图片。底色表面 token 恰好让出该不透明度，这正是图片能透过外壳框架显示、而上层表面保持不透明 token、文字保持对比度的原因。

## 曾考虑的替代方案

**作为注册表安装的插件分发。** 发布路线最先构建，随后被放弃：注册表不可变，代码一旦发布就永久公开；而桌面安装器只接受 `registry.npmjs.org` 上的名称——外部打包的产物要可安装，就必须发布到那里。

**profile bundle 或 `--patch` 覆盖文件。** 两者都能在不改动应用的前提下挂载插件，但都需要编译后的桌面应用并不提供的启动参数。

**注册具名主题，而不是叠加覆盖层。** `ctx.theme.register()` 会新增主题 id，但第三方 id 不经过内置设置 schema，因此「外观」控件无法选中它。覆盖层叠加在当前生效的内置主题之上，这也是本包覆盖两套配色而非一套的原因。

**把 Remote 的线上类型放在两个 face 都会编译的模块里。** 客户端 face 与 Host face 会各自向同一个声明文件写出一份；TypeScript 拒绝构建那个读取自身输出的程序（`TS5055`）。客户端半部现在从装配包的声明派生这些类型——`ClientRemote['themeWallpaper']`——并且完全不编译该模块。`packages/client/file-upload` 出于同一原因规避了同样的冲突。

**把图片存进设置文档，或存在浏览器存储里。** 前者会让每次设置读写都携带数兆字节；后者在浏览器 profile 被清理时就丢失图片；两者都不是用户要求的 Harness home。

## 后果

这个插件在实践中是桌面专属的：它是家族包，但它的行与配色默认值都在桌面组合里，没有其他组合挂载它。图片存储从不回收，因此放弃一次选择会把字节留到同一张图片被再次选中、或者运维人员手动删除为止。放弃选择后恢复原存储图片会重新读取其字节，而不是缓存它们。

## 测试

`tests/theme.host.spec.ts` 覆盖 Host 半部：schema 默认值、分节安装、按内容哈希的一次完整往返、同一图片的重复存储，以及各类拒绝（不支持的媒体类型、空内容、超出上限、缺失的 id）。`tests/theme.client.spec.ts` 覆盖对照 ui-theme 样式表的 token 派生、背景图片的 token 代数，以及调色面板的暂存行为：预览而不写入、保存、放弃、移除、不透明度、存储失败、存储图片不可读，以及 dispose 时释放该层。
